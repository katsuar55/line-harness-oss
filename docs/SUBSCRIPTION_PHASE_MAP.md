## 「LINE から今できること」の実態

**状態を変える操作はゼロ。** 契約カードのボタンは 3 つあるが、すべて案内で終わる:

| ボタン | 実際の挙動 |
|---|---|
| 📦 次回をスキップ | ガイドカード (手順テキスト) → 「マイページを開く」 |
| 📅 お届け日を変更 | 同上 |
| 解約・一時停止 | 同上 |

- 遷移先 = `https://naturism-diet.com/account` (Shopify 新カスタマーアカウント → Huckleberry 定期購買一覧)
- 実タップ: LINE 内 3 タップ + **外部ブラウザでログイン (メール + 6桁コード)** + 外部 4 タップ以上
- しかも現在は MENU gate OFF なので、**このカード自体が顧客に出ていない**

### WEB (PC・モバイル) では既にできる

顧客は Huckleberry のマイページから自分で スキップ / 次回ご注文日変更 / お届け日変更 /
一時停止 / 解約 / 周期変更 ができる (変更受付期限 = 次回決済日の **3 日前**まで)。
店舗スタッフも「定期購買一覧 → 契約詳細」から同じ操作を代行できる (2026-08-05 K4 で確定)。

つまり **機能が無いのではなく、LINE から届いていない**のが現状。

## リッチメニューに「サブスク」を出せる条件

現時点では **出さない**。押しても「外部ブラウザでログインしてください」と言うだけのボタンを
一等地に置くことになるため。技術的にも `rich-menus.ts` が MENU gate OFF 時は 400 で拒否する
(死にボタンを構造的に防ぐ設計)。

出せるようになる条件は 3 段階:

1. **受理レイヤー (§10-3 `sub_intents`) の実装** — LINE で **1 タップ受理** → スタッフが
   Huckleberry 管理画面で代行実行。設計上の移行前タップ数は スキップ 1 / 日付変更 1〜2 /
   一時停止 1 / 解約 2。
   **最大の前提だった「スタッフが代行できるか」は 2026-08-05 の K4 で確定済み** = 着手可能になった。
   現状は**完全未実装** (テーブル・service・route・UI・gate すべて無し)
2. **MENU gate の開放** — 🔄 **2026-08-11 Katsu 決定で条件1 (>30) と条件2 (実測が過半) は撤廃**。
   残る阻止条件は条件3 (直近 72h に実測受信) のみ。前提は数値でなく**リスクの実確認**
   (derived の日付表示が「ごろ」+ 脚注で誠実か / Flex 320px) に置き換わった。
   撤廃の根拠と確認記録は `docs/SUBSCRIPTION_GATE_CRITERIA.md` が正。
   分母 (LINE 到達可能な契約者) を動かすのは **Sprint A (連携特典 ¥300) と
   Sprint C (magic-link メール)** の仕事で、gate を閉じておくことでは増えない
3. **Phase 3 (自社課金)** — ここまで来て初めて「LINE から即時実行」= North Star 到達。
   それまでは受理 → 代行なので、反映にタイムラグがある (顧客体験としてのタップ数は 1〜2 のまま)
